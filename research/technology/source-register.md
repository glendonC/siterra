# Technology feasibility and source register

Research checked 2026-10-26; second verification pass the same day (event kickoff day). Public research notes; contains no credentials or account-specific information. `TECH-*` identifiers below are stable references for the architecture documents; entries 01 to 28 keep their IDs and were corrected in place where sources changed, 29 onward are new. Documentation inspection establishes advertised capabilities, not successful integration, account eligibility, measured latency, or guaranteed service behavior. No dependencies were installed, no accounts were used and no authenticated calls were made. The only network calls beyond page reads were public npm registry metadata queries, public GitHub API reads and Meta's unauthenticated status endpoint.

Companion notes from this pass: [stack versions](stack-versions.md), [map assets](map-assets.md), [observability](observability.md).

## Decision

Use a bounded React investigation workspace, Meta Model API, typed case records, and a durable worker. Treat data processing as reproducible scientific computation. Defer tldraw, Naïve, voice, arbitrary generated interfaces, and real-world execution. Deploy web, worker and PostgreSQL on Railway; Render is the fallback (see Hosting). Architecture decisions are engineering judgments grounded in the sources below; they are not vendor performance claims.

## Comparison: final recommendation is guided React

| Criterion | Chat-first artifacts | Open spatial canvas / tldraw | Guided adaptive React workspace |
| --- | --- | --- | --- |
| First-use clarity | Familiar, but work buried in transcript | Navigation and zoom concepts require learning | Place and case stay visible; work grows in named sections |
| Real agent composition | Feasible, but easily becomes answer attachments | Strong shape APIs; custom domain shapes required | Typed component recipes assembled from case records |
| Map interaction | Feasible in an embedded artifact | Competing canvas and map gestures | One persistent map owns geographic gestures |
| Provenance and inspection | Links can scatter across messages | Must implement evidence semantics separately | Shared source inspector from every view |
| State/reload | Requires transcript/artifact synchronization | Shape store plus authoritative case synchronization | Case projection plus small local view state |
| Accessibility/responsiveness | Strong linear structure | Spatial navigation/DOM reading order need extra work | Semantic DOM, linear narrow layout, keyboard controls |
| Visual impact | Moderate unless work escapes transcript | Strong, with disorientation risk | Strong progressive composition with persistent geography |
| Ten-day risk | Lower, but misses signature experience | Highest: shape/map integration and license gate | Moderate; domain components are useful build work |

These are design/engineering assessments, not usability-study results. Selected fallback: fixed React sections and an immediate layout swap if animated adaptive composition is unstable. Do not switch to an infinite canvas during the build.

## Other alternatives resolved

- **Plot over Recharts/ECharts:** choose Plot for explicit marks, scales, facets and annotations in a small scientific comparison set. Recharts would be a reasonable conventional React chart choice and ECharts a configurable engine, but neither has a demonstrated unmet requirement here. This is a fit judgment, not a claim that either is less scientifically capable or slower. Freeze one chart renderer; do not combine three libraries. Chart recipes must enforce units, missingness, shared period selection and source references regardless of renderer.
- **PostgreSQL queue over a hosted agent/company runtime:** bounded jobs and one existing datastore fit the P0 task graph. A durable runtime is useful only if it preserves the same case contracts, scientific checks and authority boundaries. Naïve's larger operations surface is not differentiation for this case.
- **Precomputed science over synchronous cloud raster analysis:** real, versioned preprocessing is preferable to making a demo depend on live catalog queries and raster export queues. The interface must call it precomputed. Fresh reasoning/retrieval and transparent reuse of real scientific observations can coexist.

## Model route if Spark access fails

Verified options, in the order the architecture already prescribes: another Standard Spark revision on Model API (TECH-03); Meta's documented open-weight Muse Spark Open through a hosted provider (TECH-32), which the organizer also supports with partner credits for selected participants (TECH-02). The second route is a different model; Meta's provider examples use Chat Completions-style endpoints, and Meta's Responses-only features (encrypted reasoning replay, built-in `web_search`) are not documented for those providers. It needs its own adapter tests and a separate data-use review. It must be labelled as such in the UI and trace. The Llama API is not a route (TECH-33). Labelled replay remains the UI fallback.

## Pricing and latency honesty

At the re-verified Standard rates, a hypothetical 30,000 input + 8,000 output tokens + 10 search queries costs $0.0965 before hosting, taxes, retries, caching or other tools. This is arithmetic for an example budget, not a measured typical investigation. Reasoning tokens count as output tokens and toward `max_output_tokens`. Meta offers no hard spend cap, only an alert (TECH-31), so the application ledger in [orchestration](../../docs/reference/agent-orchestration.md) is the only limiter. No latency or reliability benchmark was run; time targets in the architecture are acceptance targets. Default to Standard mode. The discounted Contributor route requires a separate data-use decision, must not receive personal or confidential information, and must not silently receive community interviews or unpublished records.

## Implications for the architecture documents (for the lead to integrate)

- [Architecture](../../docs/architecture/README.md): `store` defaults to `true` at Meta, so the adapter must send `store: false` on every request, request `reasoning.encrypted_content`, and replay full input (no `previous_response_id`). The tool-choice design cannot rely on `required` or `none` (TECH-07). Map rendering requires WebGL2 under MapLibre 6 (TECH-39).
- [Orchestration](../../docs/reference/agent-orchestration.md): a 60-second model request timeout is safe only as a time-to-first-event or inactivity limit on streamed calls; Meta exempts streams from its own time limit once output starts and recommends streaming or background mode for long generations (TECH-05, TECH-30). Retry policy matches Meta guidance; add "do not retry unchanged 413 or non-streaming 504".
- Earlier disagreement between [data contracts](../../docs/reference/data-contracts.md) and the case schema on event kinds and usage fields was resolved in contracts 1.2.0; see [observability](observability.md#contract-gaps-found-resolved).
- [Methods](../../docs/reference/data-sources-and-methods.md) pin SRTM for analytical terrain while the recommended display relief is GLO-30; see [map assets](map-assets.md).
- [Design system](../../docs/reference/design-system.md): the 450 label weight needs the variable Plex Sans package; Plex Mono has no variable package ([stack versions](stack-versions.md)).
