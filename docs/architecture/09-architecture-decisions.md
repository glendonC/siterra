# Architecture decisions and core invariants

Core technical and scientific invariants that govern every package in Siterra:

| Invariant | Rule | Enforced in |
|---|---|---|
| Authoritative case record | Every view (map, chart, card, brief, trace) is a deterministic projection of one `CaseSnapshot` revision. Records are append-only and revised by exact `EntityVersion {entityId, revision}` references; changing an input marks dependent records `stale`. | `packages/contracts`, `packages/db`, `packages/domain/src/staleness.ts` |
| Deterministic measurements and pre-registered recipes | Models never compute or edit numbers. Satellite and climate series are precomputed offline into checksummed STAC 1.1.0 bundles (`data/bundles/`) and declarative analysis recipes (`science/recipes/registry.json`). Missing data is stored as `null` with a status and reason, never `0`. | `science/`, `packages/db/src/bundle-import.ts`, `packages/contracts` |
| Pre-registered predictions before data reads (`DF-07` to `DF-09`) | In `explanation_branches`, the model proposes 2 to 4 testable predictions per explanation from catalog IDs alone, with no tools and no data values. Predictions are committed at an earlier case revision before host code reads any bundle, scores predictions (`merge@2`), and computes the minimum field-check test cover (`minimumTestCover`). | `packages/agent/src/tasks/branches/`, `packages/domain/src/branches.ts`, `packages/domain/src/test-cover.ts` |
| Layered independent validation | Every model proposal is constrained to the strict JSON Schema subset and checked by host code before commit: schema parse, entity-version reference check, verbatim source excerpt matching, numeric provenance against cited measurements/excerpts, prohibited-claims scan, and scope check (`SA-10`). | `packages/domain/src/validators/`, `packages/agent/src/tasks/` |
| Bounded autonomy and human authority | Tasks run under host-enforced round, concurrency, wall-clock, and micro-USD spend caps. No tool or API route can send external communications, spend funds, publish claims, or authorize land-use changes; `OperationalAction.externalExecutionEnabled` is `false` and actions stop at `prepared`. | `packages/agent/src/coordinator/`, `packages/db/src/reviews.ts` |
| Self-hosted geospatial and observation assets | Terrain tiles (Copernicus DEM GLO-30), imagery drapes, and STAC bundle assets are served from the application origin with SHA-256 multihash verification and HTTP Range support. | `apps/web/app/api/map-assets/`, `apps/web/app/api/case-assets/` |
