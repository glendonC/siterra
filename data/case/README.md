# Case seed

The seed of the Aït Bouguemez grazing case (`case_aitbouguemez`): what the seed loader reads to start the case record. Owned by the science and map data lane ([delivery plan](../../docs/project/delivery-plan.md)); layout in the [building block view](../../docs/architecture/05-building-block-view.md).

| File | Holds |
|---|---|
| `case.json` | Case ID, the case copy (`case`), the analysis geometry selection (ID, revision, role, geodesic area with its method, the other two areas each with its method, limitations), the paths and SHA-256 of the bundle catalog, the corpus manifest and the recipe registry, and the gold set folder |
| `geometry/ait-bouguemez-catchment.geojson` | The frozen catchment `geo_ait_bouguemez_catchment` revision 1, byte-identical to `analysis-geometry.geojson` in every bundle |
| `corpus-manifest.json` | The core corpus: one entry per source, mapped to the `Source` record of [`schemas/case.schema.json`](../../schemas/case.schema.json), with URL, licence, redistribution status, access decision and, for each stored file, its URL, size, SHA-256 and the path of its extracted text |
| `gold/RUBRIC.md` | Labeling rubric for the gold sets: claim kinds (the `Evidence.claimKind` enum), scope, statement rules, review |
| `gold/extraction.jsonl` | Extraction gold set, model draft, unsigned: a header with the corpus manifest's SHA-256 and the text extractor, then one item per located excerpt in the format of [evaluation](../../docs/reference/evaluation.md#extraction-gold-set). Built and checked by `science/pipeline/gold-extraction.py` from a private draft |
| `gold/numeric.jsonl` | Numeric gold set: every stored measurement value of every bundle Item, with bundle, period, metric, unit and checksums, generated by `science/pipeline/gold-numeric.py` |

## Case copy

The `case` object in `case.json` holds the words the case record and the screen use, from approved copy only:

| Field | Words | Source |
|---|---|---|
| `title` | Grazing and livelihoods in the Aït Bouguemez valley | [Microcopy](../../docs/reference/microcopy.md), section 1, line 2 (title) |
| `location` | Central High Atlas, Morocco | [Microcopy](../../docs/reference/microcopy.md), section 1, line 1 (location); shown on screen only, not stored in the case record |
| `objective` | Is grazing changing the shared pastures of the Aït Bouguemez valley? | The investigation question approved for the case on 2026-10-27 |
| `description` | Reported: concern about grazing pressure on shared pastures. Not established: whether vegetation has changed, or why. | [Microcopy](../../docs/reference/microcopy.md), section 1, line 4 (status) and the reading order that follows it |
| `unresolvedQuestions` | Whether vegetation has changed, or why. | The "Not established" half of the status line |

The top-level `description` describes this file, not the case.

## Corpus

The core corpus is the 13 sources with source cards plus SCI-04, taken from the [source register](../../research/science/source-register.md). [`science/pipeline/corpus-fetch.py`](../../science/pipeline/corpus-fetch.py) fetches every source marked `open`. The files stay in the ignored `data/raw/corpus/<SCI-ID>/`, each with a `.provenance.json` beside it, and their text stays in `data/interim/corpus/<SCI-ID>/`. Only this manifest is public. A source that is paywalled, or whose open copy is not confirmed as authorized, is `bibliography_only` and is never fetched.

Where a publisher refused the script or holds the article behind a paywall, the stored file is the open abstract record (Crossref or the institutional repository), as the `accessNote` of each entry says. Each entry's `excerptPolicy` (with its reason) decides what a public file may hold: `text` where the licence allows short excerpts, `offsets` where it does not or says nothing, so the excerpt is resolved from the stored file. The full text of a source is never published from this repository.

Each entry carries `language`, a BCP 47 tag checked from the stored text (function-word counts per file and per PDF page), not taken from the publisher; each stored file carries its own tag, and `languageNote` where the file mixes languages (SCI-144: body text in Spanish, site navigation in English). SCI-30 and SCI-145 have no stored text; their tag is the language of the title and abstract record the register lists.

Text locators: a PDF is located by page (1-based) in its `.text.json`; an HTML page or an abstract record by section heading and character offset into the stored text, whose SHA-256 is recorded.

Each entry carries every field of the `Source` record except the record's own `revision`, `createdAt`, `updatedAt` and `caseId`, which the seed loader sets: `accessedAt` is the latest retrieval of a stored file, or for a bibliography-only source the time of a single request to its DOI (`accessCheck`, nothing stored); `contentHash` is `sha256:` and the first stored file's SHA-256, null for a bibliography-only source; `notes` holds the access note and the excerpt policy. SCI-30 and SCI-145 carry no file: `contentHash` null, `accessStatus` `discovered`, and `accessedAt` from their access check (SCI-30's DOI reached the publisher's landing page; SCI-145's publisher answered HTTP 403).

Requirements: Python 3.12 or 3.13 and poppler's `pdftotext` and `pdfinfo` on the PATH (the stored text was extracted with poppler 26.09.0).

```
python -I science/pipeline/corpus-fetch.py data/case/corpus-manifest.json . --check-closed --write=data/case/corpus-manifest.json
```

The fetch keeps a file already stored, so a rerun only extracts its text again (a file named with a `stored_path` is checked against its SHA-256). Web pages change; a rerun after a page changed stores nothing new until the old file is moved aside, and the manifest checksum then shows the change.

## Gold sets

The gold sets follow the format in [evaluation](../../docs/reference/evaluation.md#extraction-gold-set). The extraction items are drafted by a model and are not gold until a person signs each one ([rubric](gold/RUBRIC.md)). They never enter model prompts. The extraction draft with every excerpt text stays in the ignored `data/interim/gold/`.

```
python -I science/pipeline/gold-extraction.py data/case/corpus-manifest.json . data/interim/gold/extraction-draft.json data/case/gold/RUBRIC.md "model draft (<model ID>), unreviewed" data/case/gold/extraction.jsonl
python -I science/pipeline/gold-numeric.py data/bundles data/case/gold/numeric.jsonl
```
