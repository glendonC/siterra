# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

Contracts and design tokens carry their own Semantic Versioning numbers, recorded in the entries below; release headings carry ISO 8601 dates.

## [Unreleased]

Introduced across 1.1.0 and 1.2.0: geometry roles, cautious hypothesis statuses, typed trace payloads, evidence-linked brief items, typed uncertainty, typed proposal tools and fixed sections. Introduced in 1.2.0: revision-pinned relationships and component bindings, and catalog and focus validation codes.
- Siterra STAC extension 1.0.0 and the observation bundle profile in `schemas/stac/siterra-extension.schema.json` (`https://siterra.invalid/schemas/stac/siterra/1.0.0/schema.json`): STAC 1.1.0 Collections per bundle and Items per period with the raster 2.0.0, processing 1.3.0, file 2.1.0, projection 2.1.0, eo 2.0.0, version 1.2.0 and render 2.1.0 extensions; synthetic examples `stac-collection-ndvi.json` and `stac-item-ndvi-2022-04.json`.
- HTTP API and event stream description 1.0.0 in `schemas/openapi.json` (OpenAPI 3.2.0).
- CSL-JSON bibliographies (CSL schema 1.0.2) in `research/bibliography/`, and `schemas/README.md`.
- Design tokens in the DTCG 2025.10 format in `design/tokens/siterra.tokens.json`: base scales plus computed dark and light color themes (12-step OKLCH scales, roles, data palettes and map colors), the generated stylesheet `design/tokens/siterra.css` and the contrast report `design/tokens/contrast-report.json`.
- The problem statement with cited facts, comparable places, scenes and views, analysis recipes, the evaluation harness, voice and tone with a copy lint, and the microcopy set under `docs/`; decision records ADR-0033 to ADR-0044 (autonomous firm stance, translation, scenes, recipes, comparable places, evaluation, forecasting, floating islands, the Meta model map, the color system, voice, and the component base).
- Acceptance criteria for scenes (SC), analysis (AN), evaluation (EV), language (I18N), the visual budget and copy lint (VC-04 to VC-06), model badges and usage (TR-05, TR-06), and accessibility release checks A11Y-01 to A11Y-12.
- Architecture description in the arc42 9.1 sections under `docs/architecture/`, with C4 System Context and Container diagrams.
- Decision records in MADR 4.0.0 format under `docs/decisions/`, with a decision log and the unmodified MADR template.
- `CONTRIBUTING.md` with placement, naming, identifier, documentation and commit rules; the publication gate as a how-to guide in `docs/how-to/`; the research index in `research/README.md`; `.editorconfig`.
- Decision record [ADR-0045](docs/decisions/0045-extend-the-meta-model-map-to-event-records-figures-and-whole-corpus-reading.md) (proposed): four further checked Meta model jobs (a cited drought event record, a published figure placed on the valley, a whole-corpus comparison and a Segment Anything snow experiment), with acceptance criteria EV-06 to EV-08.
- Validated CHIRPS v3.0 monthly rainfall bundle for the frozen valley catchment in `data/bundles/` (84 monthly Items, 2019 to 2025, on 33 native 0.05 degree cells; SV-01 reproduction passed), with its STAC catalog and the Copernicus and CHIRPS notices.
- Analysis recipe `season_summary` 1.0.0 with its near-normal band (terciles of the 30 wet seasons starting 1991 to 2020), registered before any event comparison ran and before any vegetation data was read; `compare_events` uses it.
- Register entries SCI-142 to SCI-144 (Chamberlin 1890, verified; Platt 1964, bibliography only; AEMET tercile categories) and the FAO terms for GIEWS excerpts in SCI-25.
- Validated Sentinel-2 vegetation record for the catchment in `data/bundles/`: monthly NDVI for 2019 to 2025 (68 months available, 16 insufficient in winter, each gap with its reason; SV-01 reproduction passed) and monthly departures against both the all-years and the leave-one-year-out same-month median, with "Contains modified Copernicus Sentinel data 2019-2025".
- Result bundles for the P0 recipes in `data/bundles/`: `season_summary` 1.0.0 for the seven wet seasons 2018/19 to 2024/25, with the six monthly totals behind each; `coverage_summary` 1.0.0 (catchment only); `aligned_antecedent` 1.1.1, marked post hoc in the bundle, the registry and the recipe page, reporting both references; and `terrain_strata` 1.0.0, three equal-area elevation bands and aspect classes with ESA WorldCover 2021 cropland and built-up excluded, for field sampling only.
- Full recipe entries for `coverage_summary`, `monthly_departure`, `aligned_antecedent` and `terrain_strata`, each saying which parts were fixed before any data was read and which were written with the first run.
- Register entry SCI-154, the GeoNames gazetteer extract for Morocco, used for map labels only.
- The science pipeline package in `science/`: 19 scripts that build every bundle from public data by HTTP range request, the machine-readable recipe registry and the pinned lock file; no model computes or edits a number, and the catchment delineation stays outside the package.
- Case seed in `data/case/`: the case record seed with the geodesic study area, the core source corpus manifest (14 sources: 12 stored openly, 2 bibliography-only; fetched by `science/pipeline/corpus-fetch.py`), and draft gold sets: 32 extraction items located by code in the stored texts, drafted by a model and unscored until a person signs them, and 350 numeric items generated from the bundles.
- The application monorepo (pnpm workspace, Next.js 16, TypeScript 6 strict, ESLint, Prettier, Vitest; Next.js telemetry disabled in every script) with the case contracts in Zod 4 and contract tests over every example; the PostgreSQL case database with append-only history (UPDATE, DELETE and TRUNCATE refused; a whole case is deleted only by the cascade for expired demo copies); the commit transaction with expected revision, the event log, the snapshot API and the event stream with replay; and the importer of the validated bundles, which verifies catalog checksums.

- Demo sessions: a visitor gets an isolated copy of the seed case with an expiry and quotas (env-configurable defaults; the real caps are a founder decision before the public demo); expiry deletes only demo copies.
- The web app arrival: the approved daylight frame over the valley in MapLibre 6 (terrain at relief x2, draped Sentinel-2 imagery, the catchment line, names on the land), the command line and key hints, the flat reading, and checks for tokens, copy and the visual budget; values are labeled fixture data until the case record is bound.
- The web app opening: the approved sentences over the lit rangeland globe, the dotted globe, and the dive into the valley that hands over to MapLibre on the same camera.
- The job queue and the worker process: pg-boss tables from its own migration plan, with @opentelemetry/api pinned to 1.9.1 and no telemetry SDK registered; the outbox dispatches each job once, by an id derived from its key; the worker runs plan jobs on PostgreSQL through the commit path, on synthetic replays until GATE-01.
- Reviews: demo review decisions through the reviews route only (real mode refused; scientific, community and livelihood, and program reviews; community and livelihood can only defer and always carries "Local consultation required"), with stale-version checks; every server-written event text comes from the approved microcopy.
- The trace store: spans per command that refuse prompt, message and tool-argument content by key prefix, accept only the listed siterra attributes, cap value lengths, and never rewrite a finished span; an owner-scoped trace route.
- The agent runtime, on replayed model outputs that stay synthetic until GATE-01: the Meta Responses API adapter (store false, strict output, retries with Retry-After, timeouts, a spend guard, the key sent only to https://api.meta.ai), the plan task, observation and source tasks with excerpt checks, validators (claim rules, numeric provenance, prohibited claims), and a coordinator with a per-command spend ledger and cancellation. No live model call has run.
- Siterra STAC extension 1.1.0: an optional per-measurement `missing_reason`; additive over 1.0.0.
- Decision record [ADR-0046](docs/decisions/0046-use-daylight-as-the-default-theme.md): daylight is the default theme, approved with the hero on 27 Oct 2026; it supersedes only the default-theme part of ADR-0042.
- Public map assets in `data/map/` (about 29 MB, every file with its size and SHA-256 in `manifest.json`): the Copernicus GLO-90 globe relief and dot grid, the rangeland biomes layer from the RESOLVE Ecoregions 2017 (preliminary), and 128 Mapterhorn terrain tiles from Copernicus GLO-30 for the valley (ADR-0018), each with its licence and notice in `data/map/licences/`; the five scripts that build them are in `science/pipeline/`.
- Staleness propagation (DF-03): when a commit materially changes a record, every current record citing its older revision becomes stale through a new revision in the same transaction, with one `entity.stale` event; state changes of workflow records are not material, and a data record moving to invalid, excluded, missing, failed, superseded or rejected is.
- Action status after reviews: an action awaiting review becomes prepared in demo mode when, for every required role except community and livelihood, the role's latest decision on the current version is an approval and its dependencies are prepared; community consultation stays listed as outstanding, and nothing is executed.
- Review requests: a task may record a request for review (revision 1, requested, demo mode, no actor, no decision time, no conditions); any other review decision from a task is refused, and a request never counts as a decision.
- `maplibre-contour` 0.1.1 (BSD-3-Clause, no dependencies) in the web app for the contour lines on the self-hosted terrain.
- The approved dive as data in `design/hero/dive-camera.json`: 133 camera keyframes at 30 fps from the globe to the arrival pose, for MapLibre at a 22 degree vertical field of view.
- Analysis tools for the agent: `compare_series` (only the departure series the aligned_antecedent recipe names, on shared periods and the same area revision, with the fixed 0 to 3 month antecedent windows and no causal statistic), `read_evidence`, `list_recipes` (blocked with a reason when no validated result exists) and `read_recipe_result` (labelled "precomputed analysis").
- Case assets on the application origin: `GET /api/case-assets/{bundleId}/{contentHash}/{path}` serves the files a validated bundle lists, hash-addressed by the bundle's content hash, only to a session whose cases hold that bundle, each file checked against its listed checksum, with byte ranges (206 and 416) and immutable caching.
- A synthetic replay of one commission of the seed case in `apps/worker/fixtures/seed-commission.synthetic.replay.json` (origin "synthetic", zero usage, no model ran), for running the slice offline in concept mode; its two answers quote stored bundle values with their measurement IDs, and replay steps can match their request so concurrent tasks replay deterministically.
- The hypothesis_comparison task: hypotheses with supporting, contradicting and missing evidence and a status word, relationships written by host code at exact revisions, no probabilities and no ranking of explanations; only the hypothesis statement may name a cause, and every number comes from the cited evidence.
- Event record tools for the agent: `read_event_record` (accepted rows of a validated event bundle for the given periods, labelled "published context, not an observation") and `compare_events` (whether each row's rainfall direction agrees with the stored season_summary tercile of its November to April season, by IDs only, direction only); tested on a fixture marked synthetic, the real event bundle waits for GATE-01.
- Map assets on the application origin (ADR-0018): `GET /api/map-assets/{version}/{path}` serves the files `data/map/manifest.json` lists to any visitor, versioned by the manifest's SHA-256, each file checked against its listed size and hash, with immutable caching and byte ranges; `GET /api/map-assets` redirects to the current manifest.
- Livelihood safeguards for the agent's livelihood_governance task: published-context evidence and field requirements only; counts of households, families, herders or people are refused in digits or words, even from an excerpt, as are titled personal names and contact details; dated years still pass.
- The web app on the case record: the arrival reads its question, area, places and credits from the case snapshot (concept mode shown as one line, its detail in the scope popover); the globe and terrain come from `data/map/`; a Sources and notices dialog credits every record, point, map layer and font, with a switch for single-key shortcuts; a first visit starts its demo copy before asking for the case; and the first path runs from the composer through the event stream to the Observations card, labelled synthetic on the replay route.
- Deployment readiness without a deployment: root scripts to migrate, load the seed, build and start the web service (bound to 127.0.0.1 unless a host says otherwise) and start the worker; `.env.example` naming every variable with placeholders only; a worker heartbeat and `GET /api/health` reporting the database, migrations, worker and outbox as states only.
- The intervention_feasibility task: two or three conditional options with assumptions, ecological and livelihood considerations, field prerequisites and required review roles, plus the host-written "Defer until the field check"; no directives, advice, predicted benefits or ranking in any response text.
- Model usage per case: `GET /api/cases/{caseId}/usage` sums the stored usage of completed model calls per route, provider, model and replay origin, counting calls without tokens or cost rather than guessing them; replay calls cost nothing and are never added to live totals.
- The brief_package task: a field-validation plan (never prepared, demo only, nothing sent or scheduled), a brief whose every line cites evidence and whose provenance cites every input, resources with unknown estimates, and one review request per role with the catalog comment; outreach, agreement and authorization claims are refused, and a missing critical dependency blocks the package with no review requested.

- The bundle importer records each measurement's and observation's own bundle version in its provenance, so superseding a bundle stales evidence that cites only its measurements; records without a stale state pass staleness on to what cites them.
- A review request's comment must be the host catalog text for its role ("Scientific review requested.", "Community and livelihood review requested." or "Program review requested."); a task never writes it.
- VC-02 exempts names on the land whether they are drawn into the map canvas or placed over it with the camera's projection; they scale with the view and are checked on the frames.
- The numeric provenance check reads a four-digit number as a year only in a date pattern or after a date word inside the case span, with "to" only inside an ascending "from X to Y" range; a count after a date word ("rose to 2000", "In 2000 households") is refused, and the repair message suggests the accepted year forms.
- Case contracts 1.6.0: ContextFeature records for the places the map names, seeded from `data/case/context-features.json`: the catchment outlet (Copernicus DEM GLO-30, with its one OpenStreetMap input coordinate credited), Tabant from GeoNames (CC BY 4.0) and the Aït Ouchi locator from SCI-04 (CC BY 4.0), each with its attribution, licence and limitations; `manifestUri` and `mapAssetUri` take a URI reference.
- Case asset links in the records are origin-relative (`/api/case-assets/...`), so a case works on any deployment; the route sends `X-Content-Type-Options: nosniff`, caches checksum matches by size and modification time, and answers an invalid range such as `bytes=5-3` with the whole file.
- Case contracts 1.7.0: model usage may record `replayOrigin` ("synthetic" or "recorded") on the replay route, and `readLineage` traces any record through its producing task to the provider, model and replay origin of its model calls, so a replayed record never reads as live.

- A brief is committed only when its provenance cites every evidence item, hypothesis and intervention it lists, so a revised input always marks the brief for reassessment.
- A task commit can no longer write an action as prepared; only completed reviews prepare an action, so no review or community condition can be skipped.
- Case contracts 1.8.0: a field-validation plan is stored on its action (objective, the decision it informs, strata as kinds of place, measurements each tied to an open gap or a hypothesis, deferred gaps with reasons, permissions and consultation steps), and a plan that leaves an open gap unmeasured and undeferred is refused.
- The map assets in `data/map/` add the summer 2025 Sentinel-2 true-colour drape for the valley (display only, with the Copernicus Sentinel notice) and widen the terrain by one z11 ring to at least 51 km around the catchment; tracked data stays under the 50 MB target.
- The direct valley view settles once from the regional view on a first visit to a case in a tab (MOT-01): one 2.7 s move with no bearing change in its last fifth, after which the names and chrome appear; any key, click, touch or wheel ends it at once and still does its own job, and reduced motion and reloads skip it.
- The web app's valley view covers the widened terrain ring at z11 with the summer 2025 true-colour drape and adds 100 m and 500 m contour lines drawn from the same terrain tiles; when the map fails, the command line and keys still work and the listing drops map-only lines; places are listed west to east after the outlet; Sources and notices lists the MapLibre and maplibre-contour licences, copied unchanged.
- The web app loads the globe, terrain and drape through the app's own map route, so a visitor's browser asks no other host; "F Read flat" is now the flat map reading (top down, north up, terrain off, graticule and scale), with the text listing as a skip link, a labelled region and the fallback when the map fails; a key hint never shows when it does nothing.

### Fixed

- Sentinel-2 duplicates: an item with no clear pixels over the catchment is now skipped when a twin of the same tile and date has some, as the preprocessing page already stated. Revision 13 of the NDVI, departure, coverage and aligned bundles (STAC `version` 13) changes seven tile-dates and moves no NDVI or departure value; the pipeline README documents the options that write a revision.
- Departure bundle revision 14: the two leave-one-year-out measurements excluded in available periods (2019-03 and 2020-03) now state why, from the counts (pixels with a reference from at least 4 other years cover 63.7% of the catchment, below the 70% coverage policy); no value changed; the bundles use STAC extension 1.1.0.
- Recipe registry: the plain-language formulas of `season_summary` and `aligned_antecedent` now state the registered tercile rule and the four antecedent windows; `all six months` stays as registered.
- Database pools now handle an idle connection the server ends (logging only the PostgreSQL code), and a test database ends its pools before it is dropped, so an intermittent "terminating connection" error no longer surfaces as unhandled.
- The worker polls its outbox every 250 ms and its plan queue every 0.5 s (the pg-boss minimum), so the first progress event of a command arrives in about half a second instead of about three (PF-05, measured locally on the replay route).
- The worker now starts its heartbeat, so `GET /api/health` reads a running worker as alive instead of reporting none.
- The brief's outreach and agreement check no longer refuses neutral wording such as "Accepted evidence shows ...", "called the agdal" or "not visited by the field survey"; a claim that anyone contacted, visited, agreed, approved or signed is still refused, with or without a named actor, after any verb, in a relative clause or in the passive.
