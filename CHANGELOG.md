### Changed

- A refused or failed data load is a named blocked input: the task's missing inputs and end event name the dataset and the reason, a task that would have succeeded ends partial, and the brief package names the blocked inputs of the tasks it reads (RL-02: an observation task without its dataset ends failed with the dataset named).
- Hypothesis statements and assessments that label an explanation confirmed or proven are refused (SA-06), and the hypothesis prompt (hypothesis_comparison@2) says so; missing evidence may still name a check that would confirm something.
- A command that treats people as the explanation because of who they are, or that names a private individual, ends its plan failed with `out_of_scope` and a host-written message, with no model call, no tasks and no brief (SA-10). The planner prompt (plan@2) carries the same scope rule and an "Out of scope." answer, and the host checks the interpretation, task questions and clarifying question without a repair turn. Herders, herding households, grazing practices, customary institutions and source wording stay in scope; the host check is a phrase list and catches wording, not meaning.
- The case analysis configuration contract (`CaseAnalysisConfig`, configuration version 1): the series pairs compare_series may align with their windows and stored decimals, the rainfall season and its recipe, and the candidate explanations (at most 5) a command tests. The Aït Bouguemez configuration is the first, in `packages/domain/src/cases/`.
- compare_series aligns only the series pairs the case configuration names, with that pair's antecedent windows and stored decimals; a case without a configuration is refused with `no_case_config`. The valley's results are unchanged.
- Case contracts 1.9.0: ExplanationBranch (predictions in a closed test grammar at revision 1, host scores and a rule-set status at revision 2) and BranchMerge (fixed merge rules, flagged conflicts) records in their own snapshot collections, the explanation_branches task kind and the propose_predictions tool; earlier versions stay valid.
- @siterra/domain scores each committed prediction met, not met or not testable from the record alone and merges branches by fixed rules (merge@1): contradicted when a necessary prediction is not met on adequate data, consistent when every testable prediction is met, cannot be assessed otherwise; it flags tests every branch predicts alike, untestable predictions and inadequate data. Wording is never read (DF-08).
- The explanation_branches task (explanation_branches@1): for each configured explanation, up to 5, the model sees target IDs and period ranges only, no values, and returns 2 to 4 predictions in the closed test grammar; the host checks them (targets in the catalog, grammar fields, at least one necessary prediction that tests the record, the wording rules and the scope rule) and commits them as branch revision 1 before any measurement, quality record or recipe result is read (DF-07). Host code then scores them, sets each status by merge@1 and writes the branch scores, the merge record and one hypothesis per branch. Each branch's model and validation events carry its branch ID (TR-07). Tested on a synthetic fixture with replayed replies; no live model call was made.
- Explanation branches name each configured series the case has no validated bundle for, and a missing season summary, as blocked inputs (the task ends partial), and offer no season target without a season summary. The compare_series runs that score co-movement predictions are traced as tool events, after the predictions commit.
- The planner (plan@3) plans explanation_branches in place of hypothesis_comparison, at most one per plan so the cap of 5 branches holds per command; hypothesis_comparison stays a task kind for stored records but is no longer planned. The DF-02 slice test now runs the drought challenge on branches over the real seed: predictions committed at an earlier case revision than their scores, rainfall compared on the same area and periods, statuses equal to merge@1 over the stored scores.
- The case analysis configuration names the bundle method of each series side, a minimum of aligned months for each pair (the valley's 12 is the aligned_antecedent applicability minimum in the recipe registry) and the field checks a prediction may name.
- Field checks in the case configuration carry a method, a basis and the explanation pairs each one separates (a configured judgment, not a result). The valley has five, one per explanation from the scientific basis table, each separating its explanation from the other four.
- @siterra/domain computes the field plan as an exact minimum test cover (DF-09): the smallest set of configured field checks that separates every explanation pair the merge leaves open, ties to the earliest in configuration order, each check naming the pairs only it separates, with a check that removing any one leaves a named pair unseparated.
- Case contracts 1.10.0: BranchMerge gains an optional `fieldPlan` (the DF-09 cover, its open pairs and the pairs no configured check separates); earlier versions stay valid.
- The explanation_branches task stores the DF-09 field plan on its merge record and lists, in each open branch's hypothesis, the field checks that separate it from the other open explanations and any open pair no configured check separates; the merge labels the pairs as configured judgments.
- STAC extension 1.1.0: `siterra:variable` adds `snow_cover_fraction` for MODIS snow cover bundles; the 25-year MODIS (`restrend_long_record`, `pixel_trend_long_record`, `season_trend_long_record`) and `snow_cover_by_band` recipes and bundles are promoted to P0.
- STAC extension 1.1.0: `siterra:variable` adds `drainage_network` for the bundle of drainage lines derived from the Copernicus GLO-30 DEM; additive over 1.1.0.
- STAC extension 1.1.0: `siterra:variable` adds `elevation_profile` for the bundle of terrain transects and `pixel_anatomy` for the bundle that opens one MODIS pixel into its finer cells; additive over 1.1.0.
- STAC extension 1.1.0: `siterra:variable` adds `elevation_surface` for the bundle of the 30 m relief grid and `optical_clear_share` for the bundle of winter Sentinel-2 clear-sky shares; additive over 1.1.0.
- STAC extension 1.1.0: `siterra:variable` adds `proposed_route` for the bundle of proposed walking routes (a proposal with access unconfirmed, never a measurement); additive over 1.1.0.
- Explanation branch merge rules (`merge@2`): a necessary `departure_sign` prediction requires at least 3 evaluated periods before it can contradict a branch (heuristic floor `[D]` reviewed in `docs/explanation/scientific-basis.md` and `research/science/analytics.md`); `CaseAnalysisConfig.whenOptionalNotMet` configures the status when all necessary predictions are met and an optional testable one is not (`"consistent"` for the valley, with the failed optional prediction named in the branch reason).
- Branch hypotheses separate evidence IDs (`supportingEvidenceIds` / `contradictingEvidenceIds`, linked to input `ev_` observations) from `measurementIds` (`meas_` IDs read by the branch's scores), and `DF-09` pairs a single standing branch with contradicted branches so every unresolved branch (`consistent` or `cannot_be_assessed`) receives a field check in `BranchMerge.fieldPlan`; valley field-check pairs cite the science review in `docs/explanation/scientific-basis.md` and `research/science/analytics.md`.
